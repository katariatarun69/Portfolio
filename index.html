About

I like extending systems that already work, not rebuilding them from scratch for the sake of it.

Most of my work has been on production WordPress sites that already had users, revenue, or live listings on them — which means the job is rarely "build from zero." It's understanding what a plugin, theme, or client system already does, and extending it without breaking what's already working.

I work close to the client side of things: gathering requirements directly, demoing features as they're built, and taking a bug report through to a fix in production rather than handing it off. Staging before production isn't a formality — it's where I catch the thing that only shows up with real data.

Development approach

Start from the existing hooks and data structures already in a codebase before adding new ones. Most WordPress problems are already solvable through the plugin API — custom code is for the gap that's actually there, not a rewrite.

Working style

Direct client communication over long requirement documents. I'd rather confirm a workflow in a five-minute call than guess and rebuild later.

On integrations

Webhooks are the connective tissue of most of the projects I've shipped — Stripe, WhatsApp, Klaviyo, Expedify. The interesting part is never the API call, it's what has to be true on your own backend before and after it fires.
